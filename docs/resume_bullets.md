## 推荐 3 条（Agent 工程 / 评测安全岗通用）

1. **【Agent Runtime】** 为开源论文 Agent 项目实现多步任务运行时：LLM 通过 function calling 自主决策"检索→阅读→引文核验→提交"的工具编排；设步数/token/连续失败三重预算与显式终态（评测中发现并修复了"单轮多调用绕过步数上限"的预算漏洞），SQLite 记录全轨迹，支持失败幂等重放恢复；配套 20 项全离线 pytest（含"注入操纵的模型调用被白名单硬边界拦截且任务不中断"的回归用例）。

2. **【安全边界与对照实验】** 设计执行层 Tool Policy：工具白名单+参数 schema 校验构成代码级硬边界（区别于提示词软防御）；构建 15 个三载体（用户消息/检索结果/工具返回）间接注入样例做三配置对照实验（n=15×3，DeepSeek 真实运行）：**45 任务违规工具调用 0 次**（function calling 范式下工具列表本身构成行为约束+白名单兜底）；同时定量暴露输出层残留面——伪装成"附参考链接"的软注入在完成任务中 8-9/15 将 canary 写入报告，据此把输出侧过滤确定为下一步，而非宣称"全面防御"。

3. **【可复现评测】** 构建 Evaluation Harness：16 个科研任务（检索/跨论文比较/事实核验/失败重试）规则判定与失败归因，指标含引文核验、无效调用、token 成本；Mock 与真实模型评测强制分离（Mock 结果显式水印），并坚持"ASR 必须与任务完成率对偶报告"（实验中 baseline 的 ASR=0 实为无输出假象，避免了一次典型的安全评测误读）。

## 使用说明

- 第 1 条适合 Agent 工程/应用岗；第 2 条适合 Agent 安全/风控岗；第 3 条适合评测岗；
- v1 工作流的既有弹药（自检索 MRR 0.99/Hit@5 100%（n=100）、注入攻防矩阵 A3 38%→0、核验循环）仍可并行使用，见项目 README 历史；
- 口径红线：所有百分比注明 n 与模式（MOCK/REAL）；MOCK 数据永远不进简历。
